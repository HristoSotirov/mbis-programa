# Програма МБИС — ТУ-София

🔗 **Линк за споделяне: https://hristosotirov.github.io/mbis-programa/**

Неофициална, удобна за четене програма за специалност МБИС (ТУ-София,
зимен семестър 2026/2027), базирана на официалния PDF файл, публикуван на
tu-sofia.bg.

Публикувана безплатно през GitHub Pages. Responsive — работи на телефон и
на компютър, и може да се инсталира като приложение/пряк път от браузъра
(вижте „PWA — инсталиране" по-долу). Групите (201А, 201Б, 202А, 202Б, 203)
се избират с тогъл бутони, с възможност за избор на няколко едновременно
(запазва се в браузъра). Автоматично скролира до днешния ден при отваряне.
Залите, отбелязани в оригинала със звездичка (напр. „зала 3401/3501*"), се
пресмятат автоматично по дни според бележките в PDF-а.

## Локално стартиране

Нужен е само Node.js (вграденият http сървър, без зависимости):

```bash
node scripts/dev-server.js
```

и отвори http://localhost:8080

## Как са получени данните

Оригиналната програма е една гъсто натъпкана PDF таблица (13 седмични
колони × ред за всяка двойка дисциплина/група), а не удобен за website
формат. `scripts/parse-schedule.js`:

1. извлича координатите на всяка дума от PDF-а (`pdftotext -bbox-layout`,
   част от `poppler-utils`);
2. възстановява структурата на таблицата по тези координати (калибровката
   на колоните е описана в коментарите на скрипта);
3. разгъва всяка клетка ("Пн–Сб 5 ч.", "Пн/Ср/Чт/Пт 5 ч. · Сб 10 ч." и
   т.н.) в реални дати и часове за 13-те учебни седмици;
4. чете бележките под таблицата ("* Лекции в понеделник: зала 3401; в
   останалите дни: 3501." и т.н.) и превръща всяка зала, маркирана със
   звездичка, в конкретна зала според деня на всяко занятие;
5. записва резултата в `public/data/events.json`, което зарежда сайтът.

Пусни ръчно презаписването с:

```bash
node scripts/parse-schedule.js <schedule.pdf> public/data/events.json
```

## Автоматична проверка за промени в официалната програма

`.github/workflows/check-schedule.yml` се стартира по график (2 пъти
дневно) и:

1. изтегля текущия PDF от tu-sofia.bg;
2. го парсва наново;
3. сравнява резултата с вече публикуваните данни;
4. ако има разлика — **отваря Pull Request** с обновения
   `public/data/events.json` (+ копие на новия PDF в `snapshots/`) и **нищо
   не публикува автоматично**.

Новата версия излиза на живо само след като администраторът (собственикът
на хранилището) прегледа разликата и **merge-не PR-а** — това е "одобрението"
по избор на потребителя. Ако автоматичното разпознаване на таблицата е
объркало нещо, PR-ът просто се затваря без merge.

## PWA — инсталиране като приложение

Сайтът има `manifest.webmanifest` и service worker (`sw.js`), така че
браузърите предлагат "Инсталирай приложение" / "Add to Home Screen":

- **Android/Chrome/Edge (компютър и телефон):** адресна лента → иконка за
  инсталиране, или меню → „Инсталиране на приложението“.
- **iOS/Safari:** Share → „Add to Home Screen“.

Логото на ТУ-София се показва и в раздела (favicon), и като икона на
инсталираното приложение/пряк път.

При всеки деплой `.github/workflows/deploy.yml` подпечатва `sw.js` с
уникален build ID (git SHA + timestamp), затова всяка нова версия на
сайта автоматично изчиства старите кешове на инсталираните потребители —
не се налага ръчно "версия нагоре". Самите данни (`data/events.json`) и
HTML винаги се зареждат първо от мрежата (network-first), така че промени
в дизайна или в програмата се виждат веднага при следващото отваряне.

## Публикуване (GitHub Pages)

1. Push-ни хранилището в GitHub (public repo, безплатно).
2. Settings → Pages → Source: **GitHub Actions**.
3. `.github/workflows/deploy.yml` пуска при всеки push към `main` и
   публикува съдържанието на `public/`.

## Структура

```
public/            сайтът, който се публикува (index.html, style.css, app.js,
                    manifest.webmanifest, sw.js, data/events.json, assets/, icons/)
scripts/           Node скриптове: парсър на PDF-а + локален dev сървър
.github/workflows/ деплой + автоматична проверка за промени
```
