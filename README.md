# Разпис МБИС — ТУ-София

Неофициален, удобен за четене седмичен календар на учебния разпис за
специалност МБИС (ТУ-София, зимен семестър 2026/2027), базиран на
официалния PDF файл, публикуван на tu-sofia.bg.

Публикуван безплатно през GitHub Pages. Responsive — работи на телефон и
на компютър. По подразбиране показва група **201**, с възможност за смяна
на групата от падащото меню (запазва се в браузъра).

## Локално стартиране

Нужен е само Node.js (вграденият http сървър, без зависимости):

```bash
node scripts/dev-server.js
```

и отвори http://localhost:8080

## Как са получени данните

Оригиналният разпис е една гъсто натъпкана PDF таблица (13 седмични
колони × ред за всяка двойка дисциплина/група), а не удобен за website
формат. `scripts/parse-schedule.js`:

1. извлича координатите на всяка дума от PDF-а (`pdftotext -bbox-layout`,
   част от `poppler-utils`);
2. възстановява структурата на таблицата по тези координати (калибровката
   на колоните е описана в коментарите на скрипта);
3. разгъва всяка клетка ("Пн–Сб 5 ч.", "Пн/Ср/Чт/Пт 5 ч. · Сб 10 ч." и
   т.н.) в реални дати и часове за 13-те учебни седмици;
4. записва резултата в `public/data/events.json`, което зарежда сайтът.

Пусни ръчно презаписването с:

```bash
node scripts/parse-schedule.js <schedule.pdf> public/data/events.json
```

## Автоматична проверка за промени в официалния разпис

`.github/workflows/check-schedule.yml` се стартира по график (2 пъти
дневно) и:

1. изтегля текущия PDF от tu-sofia.bg;
2. го парсва наново;
3. сравнява резултата с вече публикуваните данни;
4. ако има разлика — **отваря Pull Request** с обновения
   `public/data/events.json` (+ копие на новия PDF в `snapshots/`) и **нищо
   не публикува автоматично**.

Новата версия излиза на живо само след като администраторът (собственикът
на хранилището) прегледа разликата и **merge-не PR-а** — това е "одобрението"
по избор на потребителя. Ако автоматичното разпознаване на таблицата е
объркало нещо, PR-ът просто се затваря без merge.

## Публикуване (GitHub Pages)

1. Push-ни хранилището в GitHub (public repo, безплатно).
2. Settings → Pages → Source: **GitHub Actions**.
3. `.github/workflows/deploy.yml` пуска при всеки push към `main` и
   публикува съдържанието на `public/`.

## Структура

```
public/            сайтът, който се публикува (index.html, style.css, app.js, data/events.json)
scripts/           Node скриптове: парсър на PDF-а + локален dev сървър
.github/workflows/ деплой + автоматична проверка за промени
```
